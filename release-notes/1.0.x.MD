### !69 jira/JSPT-2718 — Paimon Append 优化路径系列修复

按评审项逐条修复普通 Append / Data Evolution 优化链路的正确性与性能问题：

- **eb0d68b89（R2）无桶 Append 同快照下到期合并需求丢失**：MINOR/FULL 间隔到期但数据快照未变化时，无桶 Append 无法重新进入调度；规划期间的新需求也可能被旧空计划消费。将无桶模式纳入到期规划指纹、同快照待规划标记和受保护的刷新路径，使到期需求在旧空计划结束后仍可重新规划。
- **4294ad957（R3）单文件 MINOR 任务执行失败**：`compaction.min.file-num=1` 时普通 Append 可能发布单文件 MINOR 任务，而 Paimon 原生执行器要求未启用 DV 的任务至少包含两个文件。在 MINOR 尾部发布前校验原生输入条件；普通单文件留在活跃快照，表级启用 DV 时保留合法的单文件重写能力。
- **7d3a0ff95（R4）打包平方级开销（性能优化）**：MAJOR/FULL 打包反复统计增长中的 bin，并在消费前缀时搬移剩余数组头部，大量小文件与超大文件配对场景出现平方级开销。改用 `MajorFullBin` 缓存文件数与 DV 单元数、以前缀游标消费输入，保持既有伙伴选择、任务边界和文件顺序；新增 192 组基线输出兼容检查，6 万文件场景保持原有时限。
- **02e4b07b0（R1）阻止 Data Evolution 进入不支持的 Append 路径**：Data Evolution 需要专用读写/重写流程，普通 Append 执行路径无法保证其数据正确性，历史任务恢复还可能绕过新的规划准入。在评估、扫描、规划、旧任务执行和 SUCCESS 恢复提交全链路统一拒绝；健康统计与维护资格沿用各自规则。
- **8c86644b0（R6）修复恢复测试空任务假通过**：测试夹具未满足显式优化准入，恢复场景可能序列化并恢复空集合，无法证明未完成任务可恢复。补齐 write-only 与 self-optimizing 准入配置、确保至少两个原始任务，恢复执行并提交后比较完整行值及重复数量，覆盖实际 Paimon execute/commit 链路。
- **40025f262 主键恢复发现有界化**：接受 absent successor 前先校验当前快照；出现保留缺口或探测预算需要时仅枚举一次原生快照目录。明确保留官方 Paimon 1.4.2 行为：已过期的正向 LATEST 仍导致原生提交失败并作为未解决边界显式测试。
- **be12eb43a 跨非高峰边界刷新主键规划**：在普通 HASH 规划键中捕获原生有效 ratio 并将候选选择冻结到该 ratio，不涉及 AMS 或共享 SPI 改动。
- **d0520909e 放行确认过的同快照主键 MAJOR 合并**：仅改动 Paimon 格式模块，保留现有 planner 准入检查。

### !67 jira/JSPT-2820 — 分离 Paimon 主键表提交与维护

- **问题**：主键优化提交此前强制 `write-only=false`，可能在提交返回前执行快照过期等维护动作，拉长提交路径。
- **修复**：对 HASH_FIXED / HASH_DYNAMIC 表在 committer 本地的表副本上设置 `write-only=true`，将维护动作移出提交路径。
- **保留与增强**：保留原生发布、冲突检查、提交身份与恢复语义；记录格式与 AMS 提交阶段，直接失败保留 WARN 级别与原始原因，区分嵌套事务返回与持久化完成。覆盖维护分离、动态索引、并发、恢复与可观测性测试（含 MySQL 完成恢复、外层 SQL 回滚）。

### ff49196bd — 主键表快照发布前校验读依赖（fix）

- 针对 HASH_FIXED 主键表（带删除向量 DV）：采集版本化的 executor 读证据，在每次原生 COMPACT 发布（含 CAS 重试）前，对父快照校验文件与 bucket DV 状态，同时保留 catalog 委托与原生重试策略。
- 恢复与遗留输出要求精确的 COMPACT 身份证据；不确定的发布保持可恢复，确定冲突复用既有 FULL 跳过路径。append、动态桶、未启用 DV 的提交维持原路径。
- 基于 Paimon 1.4.2 源码（ac223f47d）验证：模块 1498 项测试通过，63 个新 F1 用例通过，DV 校验与重试校验的变异测试均能检出。

### !70 hotfix/ams-typed-taskruntimes-once — task runtimes 单次物化（perf）

- 持久化优化 process 时将 task runtimes 只物化一次，避免重复物化带来的 CPU 与临时对象开销。（提交仅含标题。）

### !71 hotfix/ams-payload-streaming-encode — 优化载荷流式编码（perf）

- **优化机制**：将优化载荷直接经 1 KiB 有界缓冲序列化进 GZIP，避免完整未压缩序列化副本驻留内存，同时合并小对象的字段写；保持既有 Java 序列化 + GZIP 线格式不变，调用方持有的序列化流保持打开。
- **量化效果**：三 JVM 合成测量下，10,000 个主键任务的编码 CPU 为 14.5 ms（无缓冲流式 49.4 ms、旧实现 14.0 ms），分配字节比旧实现少 61%。
- **覆盖**：流所有权、错误处理、缓冲边界、随机载荷、10,000 任务输入的字节等价与往返校验（48 项定向测试）。

### !72 jira/JSPT-2845 — 降低 Prometheus 抓取分配（perf）

- **问题**：大型指标注册表每次抓取都对指标身份反复排序与格式化、重建固定标签列表、分组后再逐一查找。
- **优化机制**：固定元数据（名称/标签/help/类型）做快照并缓存其 hash 与标签顺序；单遍扫描活跃条目构建 metric families，复用 sample 名，每个定义每次抓取只校验一次；采集期间指标被注销时避免空查找。指标命名、标签、help、类型与过滤行为不变，Gauge/Counter 值每次抓取实时读取。
- **量化效果**：本地 277,200 样本负载下，collect 阶段分配从 704.3 MiB 降至 18.5 MiB，线程 CPU 中位数从 166.8 ms 降至 31.1 ms；全量 collect + 文本 + gzip 的 CPU 从 534.5 ms 降至 392.6 ms，标准化输出完全一致。代价：固定元数据为该测试常驻集增加约 23.5 MiB。
- **验证**：175 项组件测试与 11 项 AMS 调用方测试，新增 15 个用例（双文本协议、旧版输出对比、活值、生命周期、并发、元数据隔离）；反向过滤条件被回归测试检出。

### !73 hotfix/ams-hotpath-plan-logging — 热路径日志降级（perf）

- 将优化规划热路径上的日志降为 debug 级别，削减大规模调度下的日志量与日志开销。（提交仅含标题。）

### !74 jira/JSPT-2846 — 加固分布式 Producer 清理与诊断（fix）

- **序列化器**：Snapshot Executor 清理在创建 SparkContext 前固定 JavaSerializer，并在 Driver/Executor 两侧校验实际序列化器，避免隐式配置漂移。
- **失败诊断与脱敏**：失败结果保留有界异常链与关键堆栈；对引号、反斜杠和已知凭证的 JSON 编码形式做完整脱敏。
- **并发清理**：孤儿文件清理增加有界 `tableConcurrency`，通过独立会话并发提交 Paimon 原生 distributed 调用；保留物理表去重、取消围栏和进入 Procedure 后禁止整表重放的边界。
- **YARN 策略**：重试次数由 spark-submit 显式配置，Producer 仅校验、不再在 Driver 覆盖，避免掩盖提交策略；Paimon 0.9.0 原有执行路径不变。
- **验证**：Spark 3.5.4/Paimon 1.3.2 全部 272 项测试通过（含独立 Executor 清理与数据核对）；Paimon 0.9.0 相关 57 项通过；YARN 策略与脱敏缺陷均先由失败测试复现（YARN 检查未做真实集群验收）。

### !75 codex/paimon-catalog-scan-default — catalog 表默认值应用到存量表（fix）

- **做了什么**：加载既有主键表与 append 表（含 tag 重载）时，将 catalog 的全部 `table-default.*` 选项填充到缺失的运行时 FileStoreTable 选项；显式表选项始终优先，catalog 缓存与持久化 schema 保持不变。
- **实现要点**：选项值统一透传，用原生 `copyWithoutTimeTravel` 校验替代直接改写 TableSchema 选项；拒绝不兼容的不可变与 schema 选项，同时保留已捕获的 schema。
- **覆盖**：原生选项值、优先级、缓存隔离、重载、序列化、原生校验、捕获 schema 身份与规划一致性（27 个 table-default 用例）；`amoro-format-paimon` 模块 1680 项测试通过。
